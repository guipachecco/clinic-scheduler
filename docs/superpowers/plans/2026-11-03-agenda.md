# Agenda (entrega 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the clinic an admin agenda. It shows appointments by day, week, month and list. From it the admin creates, reschedules (including by drag and resize), edits and changes the status of appointments, and each patient record gets its appointment history.

**Architecture:**

- **Migration:** one additive migration.
- **Domain module `src/modules/appointments/`:**
  - `fields.ts`: Zod schemas, labels and the status transition rules. Pure and client-safe.
  - `rules.ts`: pure warning checks, built on `src/modules/schedule/time.ts`.
  - `appointments.ts`: server-only data functions. Every write takes an advisory lock and locks the patient row, and the DB exclusion constraint has the final word on overlaps.
- **Calendar:** a client component wrapping FullCalendar under `src/app/admin/(painel)/agenda/`. It loads events through a Server Action.
- **Appointment screens:** the create and record pages follow the patient and service screens. Actions return results and never `redirect()`.

**Tech Stack:** Next.js 16, Server Actions, Drizzle with PostgreSQL 17, Zod 4, React Hook Form, Luxon, FullCalendar 6, Vitest and Playwright.

**Spec:** `docs/agenda.md`, sections "Entrega 3: Agenda", "Banco de dados", "Dependências novas" and "Detalhes definidos na revisão do design".

## Global Constraints

### Time

- **Time zone:** `CLINIC_TIME_ZONE` from `src/modules/schedule/time.ts`.
- **Storage:** every instant is stored in UTC.
- **Display:** always in the clinic zone, whatever the browser's zone is. FullCalendar uses `timeZone: "America/Sao_Paulo"` with the Luxon plugin.

### Appointment fields

- **Patient:** must exist and not be anonymized.
- **Service:** must be active and in an active category. On edit, the current service is allowed even if it is now inactive.
- **`customLabel`:** at most 60 characters. It is required when the service is flexible and must be empty otherwise. It shows the hint "Não registre informações de saúde aqui".
- **Start:** date plus time on a 5-minute step.
- **Duration:** 5 to 720 minutes. It defaults to the service duration and is editable.
- **Occupied range:** `occupied_from = start − service.bufferBeforeMinutes` and `occupied_until = end + service.bufferAfterMinutes`. Use the service's current buffers, and recompute them on every reschedule or service change.
- **Service snapshot:** `serviceName` and `serviceDurationMinutes` copy the service at write time. `serviceDurationMinutes` is the service's default duration; the real duration is `ends_at − starts_at`.

### Creating

- **Status and source:** panel appointments start as `confirmed`, with `source: "admin"`.
- **Idempotency:** `idempotencyKey` is a UUID generated per form render. A repeated submit with the same key returns the existing appointment and does not create a second one.

### Warnings

These need an explicit "Agendar mesmo assim" confirmation:

- **outside business hours:** any part of `[starts_at, ends_at)` falls outside the intervals of its local day. An appointment that crosses midnight is checked against both days;
- **on a block:** it overlaps any time block;
- **in the past:** `starts_at` is before now.

Each warning has a code (`outside_hours`, `on_block`, `in_past`) and Portuguese text. Without the confirmation, the action returns `{ ok: false, warnings }` and writes nothing.

### Refusals

These cannot be overridden:

- **Overlap:** an exclusion violation 23P01, or a pre-check. The message is "Este horário conflita com outro atendimento das HH:mm às HH:mm.", without patient data.
- **Anonymized patient:** "Paciente anonimizado não pode ser agendado."
- **Inactive service:** "Serviço inativo."
- **Not editable:** editing or moving an appointment whose status is not `requested` or `confirmed`.

### Status transitions

- **Allowed moves:**
  - `requested` → `confirmed` or `cancelled`;
  - `confirmed` → `cancelled`, `completed` or `no_show`. `completed` and `no_show` only after `starts_at`;
  - `completed` ↔ `no_show`.
- **Final status:** `cancelled` is final.
- **Cancelling:**
  - **Reason codes:**
    - `patient_request` "Pedido do paciente";
    - `rescheduled` "Remarcado";
    - `clinic_unavailable` "Clínica indisponível";
    - `other` "Outro".
  - **Fields set:** `cancelled_by = "clinic"`, `cancelled_at = now`.
  - **No free text** is allowed with a cancellation.
- **Timestamp:** `confirmed_at` is set when an appointment becomes confirmed.

### Locking (each write, in one transaction)

1. `pg_advisory_xact_lock` on a fixed agenda key.
2. Lock the patient row `FOR SHARE` and refuse if `anonymized_at` is set.
3. Read the service.
4. Write.
5. Insert the audit row.

### Audit

- **Actions:** `appointment.created`, `appointment.rescheduled` (start, end or duration changed), `appointment.updated` (service or label changed) and `appointment.status_changed`.
- **`changes` contents:** ids, ISO instants, durations, status codes and reason codes only. Never names or labels.

### Calendar

- **Views:** `timeGridDay`, `timeGridWeek`, `dayGridMonth`, `listWeek`. The default is `timeGridWeek` from 768 px and up, and `listWeek` below that.
- **Grid hours:** `slotMinTime` and `slotMaxTime` come from the earliest start and latest end in the business hours. With no hours set, the range is 07:00 to 20:00.
- **Snap and slot duration:** `clinic_settings.slot_step_minutes`, default 30.
- **Business hours:** passed to `businessHours` using weekday numbers 0 = Sunday.
- **Blocks:** background events showing their title.
- **Event text:** the patient's nickname or first name, then " · ", then the service name or the label.
- **Status colors:** tokens in `globals.css` for both the light and the dark theme. Each status also has a lightness difference and a text label in the record:
  - requested: light yellow with a dashed border;
  - confirmed: navy;
  - completed: green;
  - no-show: bordô.
- **Cancelled appointments:** hidden by default. The "Mostrar cancelados" toggle shows them struck through.
- **Mobile:** drag and resize are off below 768 px.
- **Event data:** loaded for the visible range through a Server Action. The range never goes in the URL.

### URLs and access

- **New-appointment URL:** `/admin/agenda/novo?inicio=YYYY-MM-DDTHH:mm` is allowed, since it carries a time only. The URL never carries patient data.
- **Access:** every page and Server Action calls `requireAdmin()` first.
- **Errors:** unexpected errors become a generic Portuguese message. No `redirect()` inside actions.

### UI and process

- **UI:** Portuguese copy, identity tokens, yellow only for attention or active states, `h-11` controls, 360 px wide and dark theme supported.
- **Process:** run pnpm as `corepack pnpm`. No commits without the user's authorization.

## Review Focus

1. **Brazilian DST (if it ever returns).** An appointment at 23:30 on the night before a transition, or one crossing midnight, gets correct occupied instants and warnings. Test: unit test of `rules.ts` with a 2018-11-04 date.
2. **Two creates for the same slot at once.** Exactly one succeeds and the other gets the overlap message. Test: an integration test with `Promise.all`.
3. **Drag onto a slot that is outside hours and also overlaps.** The overlap refusal wins over the warning, and the event reverts. Test: integration (refusal before warnings) plus e2e (revert).
4. **Marking `completed` before the start time.** Refused with "Só depois do horário de início.". Test: unit test of transitions plus integration.
5. **Editing an appointment whose service became inactive.** Keeping the same service works. Switching to another inactive service is refused. Test: integration.
