# Anamnese Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grais fills in the "Anamnese Integrativa – Método ADS-USI" on the patient record in the panel, keeps several dated anamneses per patient, and downloads each one as a PDF with the clinic header.

**Architecture:** The questionnaire lives in code as a versioned template (`src/modules/anamnesis/template.ts`); the form, the zod validation, the copy-from-previous rule and the PDF are all driven by that one definition. Answers are stored as JSONB in a new `anamneses` table under the same RLS-by-clinic pattern as every other clinic table; `clinics.anamnesis_template` turns the feature on per clinic (only Grais). The PDF is rendered on the server with `@react-pdf/renderer` in a panel Route Handler.

**Tech Stack:** Next.js 16.4 (App Router, Server Actions, Route Handlers), React 19, Drizzle + PostgreSQL (RLS roles from migration 0011), zod 4, Vitest (unit + integration), Playwright, `@react-pdf/renderer` (new).

**Spec:** `docs/superpowers/specs/2026-11-10-anamnese-design.md` — read it before any task.

## Global Constraints

- Run `corepack pnpm install` first; read the relevant guide in `node_modules/next/dist/docs/` before writing Next code (AGENTS.md).
- UI copy in Portuguese; code, identifiers and comments in English.
- Template id of the first version: `integrativa-ads-v1`. Old template versions are never deleted from code.
- Field limits: short text 200 characters, long text 5,000 characters; `answers` total ≤ 200 KB (DB CHECK). No field is required.
- Sections 13 (`diagnostico`) and 14 (`protocolos`) are never copied into a new anamnesis.
- No anamnesis content (answers, question ids or labels) in `audit_logs`, logs, URLs, page titles (`metadata.title` is fixed: "Anamnese"), error messages, or browser storage (`localStorage`/`sessionStorage`/IndexedDB).
- Audit actions: `anamnesis.created`, `anamnesis.updated` (at most one per anamnesis per 30 minutes), `anamnesis.completed`, `anamnesis.reopened`, `anamnesis.deleted`, `anamnesis.pdf_generated`; `entityType: "anamnesis"`, `entityId` = anamnesis id, `changes: { patientId }` only.
- Every module function takes `clinicId` first and runs inside `inClinic`; every page, action and route calls `requireAdmin()` (actions check `getSession()` first, see Task 5).
- PDF file name `anamnese-AAAA-MM-DD.pdf` (the anamnesis date); response header `Cache-Control: no-store`.
- Copy the labels and help texts **verbatim** from `C:\Users\Guilherme\Videos\Retiro 2026\ANAMNESE METODO ADS CASO CLINICO ALUNOS.docx` (outside the repo; extract the text from `word/document.xml`), fixing only spelling ("Fórceps", "Precisou de oxigenação ou UTI neonatal?"). Leave out the post-graduation header lines.

## Review Focus

- A save that arrives after the session expired must come back as `{ ok: false, reason: "session" }`, never as a redirect that throws away the typed text → test in Task 5 (e2e: clear cookies, type, see the message, text still in the field).
- Two autosaves fired in quick succession from the same tab must not conflict with each other (the second uses the `updatedAt` returned by the first) → test in Task 5 (type, wait < debounce, type again, no conflict message, both texts saved).
- Very long answers (5,000 characters with no line breaks) must wrap and break across pages in the PDF without being cut → test in Task 4 (render a long answer, the PDF has ≥ 2 pages and contains the last word).
- Accented text (ã, ç, é, õ) must come out right in the PDF → test in Task 4 (extracted text contains "Gestação" and "Fórceps").
- A clinic without `anamnesis_template` (e.g. another clinic opening `/admin/pacientes/<id>/anamneses/<id>` or the PDF URL directly) gets 404 → test in Task 3 (module returns null) and Task 5 (e2e 404).
