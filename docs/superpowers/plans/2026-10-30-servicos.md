# Serviços (Agenda, entrega 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The clinic manages service categories and services (duration, buffers, price, flags) in the admin panel, with a built-in flexible "Avaliação / encaixe" service.

**Architecture:** One additive migration adds `services.is_flexible` and seeds the "Outros" category and the flexible service. The domain module `src/modules/services/` holds a pure, client-safe `fields.ts` (Zod schemas, slug, price parsing, labels) and a server-only `services.ts` (data functions with audit). Thin routes live under `src/app/admin/(painel)/servicos/`, where every page and Server Action calls `requireAdmin()` first. This follows the same pattern as `src/modules/patients/` and `src/app/admin/(painel)/pacientes/`.

**Tech Stack:** Next.js 16 App Router + Server Actions, Drizzle + PostgreSQL 17, Zod 4, React Hook Form, Vitest (unit + real-PostgreSQL integration), Playwright.

**Spec:** `docs/agenda.md` (sections "Entrega 1: Serviços", "Banco de dados", "Detalhes definidos na revisão do design")

## Global Constraints

- **Service fields:**
  - categoria (required, an existing category);
  - nome (2–80 chars);
  - descrição (≤ 500);
  - duração padrão (5–720 min);
  - preparo antes and intervalo depois (0–240 min each);
  - preço in cents (≥ 0, optional);
  - forma de exibir: `fixed` "Preço fixo" | `starting_at` "A partir de" | `on_request` "Sob consulta" | `hidden` "Oculto". `fixed` and `starting_at` require a price; this is DB check `services_price_display_check`;
  - exige confirmação;
  - aceita agendamento online;
  - orientações de preparo (≤ 1000);
  - ativo;
  - ordem (integer ≥ 0).
- **Category fields:** nome (2–60), ativo, ordem.
- **Slugs:**
  - Generated from the name: lowercase, accents removed, non-alphanumerics become `-`, trimmed. They must match the existing check `^[a-z0-9]+(-[a-z0-9]+)*$`.
  - Unique. A collision becomes a field error on the name: "Já existe um serviço com este nome." / "Já existe uma categoria com este nome."
  - The slug is set on create and kept on rename. Online links will use it later.
- **No deletion** of services or categories. They are deactivated instead.
- **Flexible service:**
  - The migration seeds category "Outros" (slug `outros`) and service "Avaliação / encaixe" (slug `avaliacao-encaixe`) with these values: duration 30, buffers 0, `price_display = 'hidden'`, `requires_approval = false`, `online_booking_enabled = false`, `is_active = true`, `is_flexible = true`.
  - `is_flexible` is never editable through the panel.
- **Audit:** `service.created`, `service.updated` (`changes: { fields: string[] }`), `service_category.created` and `service_category.updated`. Each records `actorType: "admin"`, `actorUserId` and the entity id.
- **Price input:** typed as Brazilian currency ("1.250,00", "R$ 90", "90,5"), stored as integer cents, and displayed as "R$ 1.250,00".
- **UI:**
  - Copy in Portuguese.
  - Identity tokens: `bg-primary` for the main action; yellow `bg-highlight` only for active/attention states, never as text on light backgrounds.
  - Controls are `h-11`.
  - Layout works at 360 px and in the light and dark themes.
- **Process:**
  - The migration is additive. Do not edit existing migrations.
  - Run pnpm as `corepack pnpm`.
  - No commits without the user's authorization.

## Review Focus

- **Renaming a service to a name whose slug collides with another service:** the expected result is a name field error, not a 500. Test: integration.
- **Price display set to "Preço fixo" with an empty price:** the expected result is a field error on the price, before the DB check. Test: unit schema plus integration.
- **Deactivating the only active service of a category, or deactivating a category that still has active services:** both are allowed. The category list shows inactive services as inactive. Test: integration.
- **Price typed "1.250,5":** it becomes 125050 cents. A value with letters is rejected. Test: unit.
- **The flexible service is edited through the form:** `is_flexible` stays true. Test: integration.

### Task 2: Services module

**Files:**

- Create: `src/modules/services/fields.ts` with its test `src/modules/services/fields.test.ts`
- Create: `src/modules/services/services.ts` (`import "server-only"`) with its test `tests/integration/services.test.ts`

**Interfaces:**

- Consumes: Task 1 schema; `db`, `isUniqueViolation` from `src/db`; the audit table.
- Produces (`fields.ts`):
  - `slugify(name: string): string`;
  - `parsePriceToCents(input: string): number | null`. Returns `null` for empty input; throws nothing. An invalid value is reported by the schema.
  - `formatCents(cents: number): string`, giving "R$ 1.250,00";
  - `PRICE_DISPLAYS: readonly { value; label }[]`;
  - `serviceFormSchema`: raw strings and booleans in, DB-ready values out. Keys: `categoryId, name, description, durationMinutes, bufferBeforeMinutes, bufferAfterMinutes, price, priceDisplay, requiresApproval, onlineBookingEnabled, preparationInstructions, isActive, sortOrder`. `price` comes out as `priceCents`.
  - `categoryFormSchema` with keys `name, isActive, sortOrder`;
  - the input and output types of both schemas.
- Produces (`services.ts`):
  - `type ServiceResult = { ok: true; id: string } | { ok: false; fieldErrors: Partial<Record<string, string>> }`;
  - `listCatalog(): Promise<{ id; name; slug; isActive; sortOrder; services: ServiceListItem[] }[]>`, ordered by category `sortOrder` then name, and services by `sortOrder` then name. Inactive items are included.
  - `listActiveServices(): Promise<ActiveService[]>`, for the agenda later. Each item is `{ id, name, categoryName, durationMinutes, bufferBeforeMinutes, bufferAfterMinutes, isFlexible }`, from active services in active categories only.
  - `getService(id): Promise<ServiceRecord | null>`. It returns null for a non-UUID or a missing id.
  - `createService(values, actorUserId)`, `updateService(id, values, actorUserId)`, `createCategory(values, actorUserId)` and `updateCategory(id, values, actorUserId)`, all returning `ServiceResult`.
